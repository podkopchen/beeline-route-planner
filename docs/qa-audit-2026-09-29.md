# Аудит RouteFlow — 2026-09-29

Проверены backend/frontend проверки, реализация auth/CORS, API client, explanation lifecycle, дорожный кэш, optimizer и replan. Это аудит с точечными исправлениями, а не подтверждение отсутствия любых ошибок.

## Исправлено

1. **CORS/auth:** session middleware перехватывал OPTIONS без cookie и возвращал 401 без CORS headers. Регрессионный тест до исправления упал с 401 вместо 200. CORS теперь внешнее middleware; разрешённый origin получает preflight и читаемый 401, чужой origin отклоняется.
2. **Полный road geometry cache:** `zip(..., strict=True)` сравнивал N legs и N+1 origins. На полном cache hit возникал ValueError. Тест воспроизвёл ошибку; origin list теперь обрезан до N. Provider не нужен для cache hit.
3. **Объяснения:** helper не передавал plan_kind/traffic_profile и всегда получал optimized/standard. Теперь RoutePanel передаёт текущий контекст; тесты проверяют baseline/peak и event ID.
4. **Гонки ответов:** позднее объяснение первой заявки могло показаться у второй. Добавлен generation guard и сброс при смене маршрута/контекста. Отдельно отменяется применимость pending canonical geometry после успешного replan; добавлен тест с запоздавшей ошибкой.
5. **Истечение сессии:** POST replan/geometry раньше не вызывал session-expired, в отличие от GET. Единая обработка теперь в authRequest, auth endpoints исключены.
6. **Replan territory accounting:** `_assemble_plan` считал неназначенными заявки всех территорий при локальном плане. Теперь considered pool ограничен base.mode; все девять событий проверяют точное множество assigned/unassigned/cancelled/urgent и отсутствие дублей.
7. **Повторяемые проверки:** pytest из project root не находил app (22 collection errors). Добавлен pythonpath в backend/pytest.ini. Ruff получил локальный src/backend config, чтобы группировка импортов не зависела от cwd; два test files отформатированы. CLI bootstrap imports имеют явное исключение E402. Backend PowerShell runner прекращает выполнение при ненулевом exit code.
8. **Vitest concurrency:** параллельный запуск всех JSDOM workers вместе с backend вызвал четыре timeout, включая старые тесты. maxWorkers=2/minWorkers=1 исправляет перегрузку; таймауты тестов не увеличены. Обычная npm test проходит.

## Открытые логические дефекты

Эти пункты требуют отдельной доработки алгоритма и новых предметных fixtures; прежний статус done не является доказательством их выполнения.

- **P0 REPLAN:** build_replanned_plan вызывает optimizer только для base. После события используются локальные вставки/удаления; unavailable visits становятся unassigned без поиска других инженеров. Требование VRPTW для всего mutable suffix и минимизации изменений не реализовано.
- **P0 cancellation:** `_remove_mutable` удаляет stop, но `_assemble_plan` сохраняет legs следующих stops от старого predecessor. После удаления промежуточного визита километраж/время входящего участка могут быть неверны. Также отсутствующая в маршрутах заявка классифицируется cancellation_too_late без проверки, была ли она вообще назначена.
- **P1 reserve policy:** `_emergency_reserve` создаёт резерв для любой территории, а согласованная политика разрешала только east. Ограничение повлияет на southeast/southcenter urgent outcomes; его нельзя выдавать за выполненное.
- **P1 diff:** reassigned/rescheduled остаются default empty; при локальной перестройке urgent suffix изменённые времена не проецируются в diff. Факты diff нужно вычислять сравнением двух планов.
- **Optimizer limitation:** solution_limit=1 означает первое решение OR-Tools. Лексикографические веса не доказывают глобальный optimum. Фиксированная оценка 1000 км на arc также не проверяется против произвольного будущего routing input. Для текущих synthetic fixtures тесты зелёные; универсальная гарантия отсутствует.
