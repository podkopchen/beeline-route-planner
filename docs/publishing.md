# Публикация репозитория

Корень Git — `beeline-route-planner/`, не весь родительский workspace. В проекте уже разделены backend, frontend, scripts, docs и generated data; переносить их ради внешнего вида не требуется.

## Что включать

Код, тесты, manifests/lockfile, документацию, `.env.example` и три необходимых кэша: `geocache.json`, `road_matrix_cache.json`, `road_geometry_cache.json`. Их содержимое не менялось. Старый объединённый `road_cache.json` остаётся локальным и игнорируется.

Оригинальные данные организатора не копируются в публичный репозиторий. Соседний `Датасет/` необходимо получить отдельно: структура описана в README. Без него новый clone не сможет рассчитать планы. Контрольные CSV не являются входом ни приложения, ни публикации.

## Перед отправкой

1. Проверьте право распространять generated caches, предоставленный логотип и производные данные. Общая лицензия на чужие материалы автоматически не назначается.
2. Выполните `.\backend\.venv\Scripts\python.exe scripts/check_repository.py`, `scripts/smoke.ps1` и ручной checklist. Preflight проверяет ASCII-имена, размер файлов, наличие кэшей и согласованность manifests, но не заменяет проверку секретов в Git. Известные логические ограничения перечислены в отчёте аудита.
3. Установленный Git должен быть доступен в PATH. Из корня проекта:

```powershell
git init
git add .
git status --short
git diff --cached --stat
git diff --cached --check
git ls-files
```

4. До commit проверьте список: никаких `.env`, `.venv`, `node_modules`, control CSV, персональных файлов, ключей или логов. `.gitignore` не удаляет файлы из уже существующего индекса: ранее добавленные секреты требуют отдельного удаления из истории и ротации.
5. Только после проверки создайте commit и добавьте свой remote. Эти действия автоматически не выполнялись.

Demo-пароль из README предназначен только для локальной демонстрации. Не используйте его при доступном из сети развёртывании. Production authentication и self-hosted routing требуют отдельной настройки.
